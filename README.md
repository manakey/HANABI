# Hanabi Chat

Node.js (Express) + Socket.IO で作ったLINE風リアルタイムチャットアプリです。

## 機能
- 未ログイン時はトップページ(ホーム)を表示、ログイン/新規登録へ進める
- メールアドレス + パスワードでログイン／新規登録(JWTトークンによるセッション管理)
- パスワードリセット(メール送信、要SMTP設定)
- 2段階認証(TOTP、Google Authenticator等のアプリに対応)
- テキスト送信・画像送信・スタンプ送信(すべてリアルタイム、Socket.IOでpush配信)
- 1対1チャット／グループチャット作成
- グループ管理(メンバー追加・削除、管理者権限、グループ名/アイコン変更、退出)
- アイコン変更(絵文字＋背景色)、チャットごとの背景画像変更
- 音声通話・ビデオ通話(WebRTC、Socket.IOをシグナリングに使用、1対1)。通話ボタンは1つに統合されており、通話中にマイク・カメラをそれぞれいつでもON/OFF切替できます(Zoom風)
- グループ通話(WebRTCメッシュ構成。少人数のグループ向け、目安3〜6人程度)。こちらもマイク・カメラを個別に切替可能
- チャットごとの通知オフ(ミュート)設定、着信音・通知音
- ユーザーのブロック機能(ブロックすると相互にメッセージ送信・チャット作成ができなくなります)
- 既読表示(自分が送った全メッセージに表示)
- メッセージの削除、返信・引用、リンクプレビュー、未読バッジ
- プッシュ通知(アプリを閉じていても新着メッセージ・着信を通知、要VAPIDキー設定)
- ダークモード(サイドバーの🌙ボタンで切替、端末設定に応じて自動判定も対応)
- モバイル対応レイアウト(スマホ幅ではチャット一覧とトーク画面を1画面ずつ表示)
- PWA対応(スマホのホーム画面に追加してアプリのように使える)。iPhone/iPadで未インストールの場合は上部に案内バナーを表示
- テーマカラーはLINE公式ブランドカラー(#06C755 / LINEフォレストグリーン)を採用

## パスワード認証について

以前はメールアドレスのみでログインできる簡易認証でしたが、現在はパスワードが必須です。

- **新規ユーザー**: 表示名とパスワード(6文字以上)を入力してアカウント作成
- **パスワード導入前から使っていた既存ユーザー**: 次回ログイン時に「安全のためパスワードを設定してください」という画面が自動的に表示されます。新しいパスワードを1回設定すれば、以降は通常通りパスワードでログインできます
- ログイン状態はJWTトークンとしてブラウザに保存され、約30日間保持されます

**重要**: `.env`(またはデプロイ先の環境変数)に `JWT_SECRET` を設定してください。設定しない場合、サーバーはランダムな値で起動しますが、**サーバーが再起動するたびに全員が再ログインを求められます**。

## データの保存について
ユーザー・チャット・メッセージは **PostgreSQL** に保存されます(以前のバージョンはJSONファイル保存でしたが、永続性の問題があったためPostgreSQLに移行しました)。

Railwayで「PostgreSQL」アドオンを追加すると `DATABASE_URL` という環境変数が自動的に注入され、アプリはそれを使って接続します。手動での追加設定は不要です。

初回起動時に必要なテーブル(`users` / `chats` / `messages`)は自動的に作成されます(`db.js`の`initSchema()`)。

### 以前の db.json からの移行

もし以前のJSONファイル版で運用していたデータ(`db.json`)がある場合、以下のコマンドで一度だけPostgreSQLに移行できます。

```bash
npm run migrate
```

`DATABASE_URL` が設定された状態で実行してください。移行が完了したことを確認できたら、`db.json` は削除して問題ありません。

画像は **ブラウザ側で自動的にリサイズ・圧縮**(長辺480px・JPEG圧縮)してからアップロードされるので、
1枚あたり数十KB〜100KB程度に収まります。保存先は次のように自動で切り替わります。

- **Cloudinary の環境変数が設定されている場合** → Cloudinaryに保存（推奨・本番向け）
- **設定されていない場合** → サーバーの `uploads/` フォルダに保存（ローカル開発向け・簡易）

**注意:** Render / Railway 等の多くのホスティングはディスクが「エフェメラル」（再デプロイやスケールで消える）です。
PostgreSQLに保存されるデータ(ユーザー・チャット・メッセージ)は影響を受けませんが、画像を
ローカルディスク(`uploads/`)に保存している場合は消えてしまうため、下記のCloudinary設定を推奨します。

### Cloudinary の設定方法（無料・画像保存をディスクから切り離す）

1. https://cloudinary.com/users/register/free で無料アカウントを作成（無料枠: ストレージ25GB・月間帯域25GB）
2. ダッシュボードの「Product Environment Credentials」から次の3つをコピー
   - Cloud Name
   - API Key
   - API Secret
3. ローカルで試す場合は `.env.example` を `.env` にコピーして値を埋める
   ```bash
   cp .env.example .env
   ```
4. Render/Railway等にデプロイする場合は、ダッシュボードの環境変数（Environment Variables）に同じ3つを設定する
   - `CLOUDINARY_CLOUD_NAME`
   - `CLOUDINARY_API_KEY`
   - `CLOUDINARY_API_SECRET`

これで画像はサーバーのディスクを一切使わず、Cloudinary側に保存されるようになります。圧縮とCloudinaryの組み合わせにより、Renderなどの無料プランのディスク容量やRailwayの0.5GB制限を心配する必要はほぼなくなります。

### プッシュ通知(Web Push)の設定方法

アプリを閉じていても、新着メッセージや着信をOSの通知として受け取れます。

1. ターミナルで以下を実行してVAPIDキーペアを生成する
   ```bash
   npx web-push generate-vapid-keys
   ```
   `Public Key` と `Private Key` が表示されるのでコピーしておく
2. `.env`(またはデプロイ先の環境変数)に設定する
   ```
   VAPID_PUBLIC_KEY=xxxxxxxx
   VAPID_PRIVATE_KEY=xxxxxxxx
   VAPID_SUBJECT=mailto:you@example.com
   ```
3. ブラウザでログインすると通知の許可ダイアログが表示されるので「許可」を選ぶ

**注意点:**
- HTTPS環境でのみ動作します(localhostは例外的にOK)。Render/Railway等にデプロイすれば自動でHTTPSになります
- iPhoneのSafariでプッシュ通知を受け取るには、アプリをホーム画面に追加(PWA化)する必要があります。現状は通常のSafariタブでは通知が届かない場合があります
- 通知アイコンは `public/icons/icon-192.png` を参照する設定になっています。お好みの192×192pxの画像を配置すると通知にアイコンが表示されます(未配置でも動作はします)

### ホーム画面への追加方法(PWA)

**iPhone(Safari)の場合**
1. SafariでアプリのURLを開く
2. 下部の共有アイコン(□に↑)をタップ
3. 「ホーム画面に追加」を選択

**Android(Chrome)の場合**
1. ChromeでアプリのURLを開く
2. 右上の「⋮」メニューを開く
3. 「アプリをインストール」または「ホーム画面に追加」を選択

**PC(Chrome/Edge)の場合**
- アドレスバー右側に表示されるインストールアイコンをクリック

ホーム画面に追加すると、ブラウザのUIなしで独立したアプリのように起動できるようになり、iPhoneでもプッシュ通知が届くようになります。

## ローカルで動かす

```bash
npm install
npm start
```

ブラウザで `http://localhost:3000` を開きます。別のブラウザ／シークレットウィンドウで別のメールアドレスでログインすると、2人のユーザーとして会話・通話を試せます。

## デプロイできるサイト

Socket.IO はWebSocketの永続接続を使うため、**常時起動するサーバー（Node.jsプロセス）を維持できるホスティング**を選ぶ必要があります。Vercel / Netlify のようなサーバーレス系はWebSocketの永続接続に不向きなので基本的に非推奨です。

### おすすめ（無料枠あり・WebSocket対応）

1. **Render** (https://render.com)
   - 「New +」→「Web Service」→ このリポジトリを接続
   - Build Command: `npm install`
   - Start Command: `npm start`
   - 無料プランはしばらく使わないとスリープします（再アクセス時に起動に数十秒かかることがあります）

2. **Railway** (https://railway.app)
   - 「New Project」→「Deploy from GitHub repo」
   - 自動的に `npm install && npm start` を検出して起動します
   - 無料枠は使用量ベース（クレジット制）

3. **Fly.io** (https://fly.io)
   - `fly launch` でDockerfileなしでもNode.jsアプリを自動検出してデプロイ可能
   - WebSocketも問題なく利用可能

4. **Glitch** (https://glitch.com)
   - コードをそのままアップロードしてすぐ動かせる、試作向けのサービス
   - 常時稼働ではないため本番向きではありません

### 適さないサービス
- **Vercel / Netlify**: サーバーレス関数ベースで、Socket.IOの永続WebSocket接続の運用に工夫が必要（不可能ではないですが標準構成では動きません）。静的サイトやAPIのみのプロジェクト向けです。

### デプロイ時のチェックリスト
- [ ] `package.json` の `start` スクリプトが `node server.js` になっている（設定済み）
- [ ] `PORT` は環境変数から取得している（設定済み： `process.env.PORT`）
- [ ] 画像アップロードを本番運用するなら外部ストレージへの切り替えを検討
- [ ] HTTPS化（Render/Railway/Fly.ioは自動でHTTPS化されます）
